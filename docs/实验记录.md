# 实验记录

每次采集或受控实验都必须登记。这份记录是报告"实验严密"章节的原始证据，也是答辩时解释异常的依据。

---

## 一、记录规则

- 一次实验（一个批次）一条记录，不按站点逐条记
- 实验开始前先填"计划"部分，结束后补"结果"部分
- 任何异常剔除都要写清规则和数量
- 换了网络、换了机器、换了时段，必须另起一条记录

---

## 四、必须记录的控制变量

真实站点实验：

- 同一台机器、同一网络、同一时段窗口
- 浏览器禁用 QUIC
- 冷缓存
- 固定重复轮数（默认 5 轮）
- 抓包与加载测量分开执行

受控实验：

- WSL 版本与内核版本
- `tc netem` 的延迟参数
- `ip route` 的 initcwnd 设定值
- 测试页面对象数与单对象大小
- 每组重复轮数

---

## 五、异常与剔除

- 剔除规则：四分位距（IQR），超出 `Q1 - 1.5×IQR` 到 `Q3 + 1.5×IQR` 视为异常
- 必须记录：剔除发生在哪个站点、第几轮、剔除前后的样本数
- 站点整体不可达：记录原因（DNS 失败、超时、证书错误），从统计中剔除，并在报告里说明

## 六、正式记录

### 记录编号：EXP-20261101-01

日期：2026-11-01
执行人：B
实验类型：受控实验

环境：
- 机器：本机 Windows
- 操作系统：Windows 11 家庭版，build 26200
- 网络：本机有线/无线接入（WSL2 虚拟网卡 eth0 与宿主同网段）
- 抓包后端：本实验不做抓包（B 只做浏览器侧测量）
- 浏览器：Chrome 156.0.8078.74（`--disable-quic --disable-extensions`，每轮独立临时 profile）
- WSL 版本：WSL 2.7.3.0，发行版 lab-ubuntu（Ubuntu 24.04），内核 6.6.114.1-microsoft-standard-WSL2

计划：
- 站点数量：受控平台 1 个（`http://172.18.65.146:8080/`），四组 initcwnd
- 每站重复轮数：每组 5 轮
- 抓包时长：不适用
- initcwnd 设定值：2 / 4 / 10 / 20 MSS（`ip route` 默认路由与 on-link 网段路由同时设置）

结果：
- 成功站点数：4 组 × 5 轮 = 20 轮全部成功（每条记录均通过 `validate_pageload`）
- 失败站点及原因：无
- 异常剔除规则与数量：IQR 规则，本批次无剔除
- 数据文件：data/processed/pageload.csv（site = lab-2 / lab-4 / lab-10 / lab-20）
- 结论或观察：同一页面（21 个请求、1 235 397 byte）在 60 ms RTT 下，`load_ms` 中位数随 initcwnd 单调下降：728.4 / 599.3 / 595.2 / 467.6 ms；`ttfb_ms` 稳定在 65.8~66.1 ms，`transfer_bytes` 恒定，说明平台的时延与窗口参数可稳定控制；lab-10 组出现一个 545.2 ms 的偏低样本，未超出 IQR 边界

备注：
- 测试页为 20 个精确 61440 byte 的合法 PNG 加 1 个索引页
- 采集前逐组确认 `tc qdisc` 与 `ip route` 已生效，采集后清除 netem 规则并恢复 initcwnd=10
- WSL2 虚拟机会在空闲约 8 s 后自动关机，采集期间需保持一个常驻会话，否则连接被拒绝

### 记录编号：EXP-20261101-02

日期：2026-11-01
执行人：B
实验类型：真实站点

环境：

- 操作系统：Windows 11 家庭版，build 26200
- 网络：本机接入网络，同一时段窗口内连续采集
- 抓包后端：不适用（与 A 的抓包采集分开执行）

计划：
- 站点数量：25
- 每站重复轮数：5
- 抓包时长：不适用
- initcwnd 设定值：不适用（真实站点由服务器侧决定）

结果：
- 成功站点数：25 / 25；累计 122 / 125 轮，完整率 97.6%（sina 缺第 1、4 轮，taobao 缺第 3 轮，均为导航超时）
- 失败站点及原因：无整站失败；单轮失败见上，未重采
- 异常剔除规则与数量：按 `load_ms` 的 IQR 规则统计，25 站共 0 轮被判异常
- 数据文件：data/processed/pageload.csv（真实站点 122 条 + 受控实验 20 条，共 142 条、29 个 site）
- 结论或观察：站点间 `load_ms` 中位数差异极大（36kr 304 ms 至 sina 28 496 ms），说明直接比较站点原始加载时间没有意义，必须与 `transfer_bytes` 和 initcwnd 联合分析；amazon（1 633 byte）与 yahoo（3 669 byte）返回的是极小的拦截页而非正常首页，第 5 章做相关性分析时应作为数据质量提示，或在正文中说明其代表性下降

备注：
- 站点清单经可达性预检确定：原 22 个候选中 6 个不可达（google 超时、youtube 超时、wikipedia 连接重置、cloudflare 超时、nytimes 超时、mit 域名无法解析），另探测 14 个补充候选，其中 reddit、bbc 不可达，最终从 28 个可达站点中取 25 个
- 全部记录 `quic_disabled=true`、`cache_mode=cold`，均通过 `validate_pageload`；DNS 命中系统缓存时 `dns_ms` 记为 0
- 采集时段 2026-11-01 19:55-20:10（UTC 11:55-12:10），顺序执行，同一时段窗口
