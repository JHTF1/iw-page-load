# 第 4 章 实验平台与指标

本章说明数据是怎么测出来的。全章围绕两个问题展开：其一，如何在真实站点上稳定地重复测量页面加载时间；其二，如何在一个参数可控的平台上验证 initcwnd 与加载时间的因果关系。前者提供外部效度，后者提供内部效度，两类证据的互补关系在第 5 章讨论。

## 4.1 实验设计概览

实验分两条线，参数与产出均写入数据字典与实验记录：

- **真实站点线**：对 25 个真实网站首页各采集 5 轮，得到 `pageload.csv` 中每个站点的加载时间分布，与 A 抓包得到的服务器侧 initcwnd 按 `site` 合并，回答"initcwnd 与加载时间是否相关"；
- **受控实验线**：在 WSL2 中架设固定内容的测试站点，人为设定 RTT 与 initcwnd 四档取值，观察同一页面在不同初窗下的加载时间变化，回答"initcwnd 是否导致差异"。

## 4.2 真实站点实验流程

**站点选择。** 候选清单先做可达性预检再定稿：原 22 个候选各测 1 轮，6 个站点不可达（google、youtube、cloudflare、nytimes 导航超时，wikipedia 连接重置，mit 域名解析失败）；再补测 14 个候选，reddit、bbc 仍不可达，最终从 28 个可达站点中选取 25 个，覆盖搜索、电商、门户、视频、社区、技术、新闻、企业等类目，国内 18 站、国际 7 站。不可达是网络环境所致，与 initcwnd 无关，筛除后统计口径保持一致。

**采集协议。** 每站连续 5 轮，全部在同一个时段窗口内顺序执行，同一台机器、同一网络接入，避免跨时段网络波动混入站点间的比较。为避免浏览器并发干扰，任意时刻只运行一个测量进程。本批次实际取得 122 / 125 轮，完整率 97.6%：sina 缺第 1、4 轮，taobao 缺第 3 轮，均为导航超时未重采；25 个站点均保留了至少 3 轮，满足后续按站点取中位数的要求。

**数据质量提示。** 除不可达站点外，amazon 与 yahoo 的 `transfer_bytes` 仅千余字节，实际返回的是防爬拦截页而非正常首页；这类记录按字段规范保留，但第 5 章在解释站点间差异时必须注明其代表性下降。

**冷缓存与协议约束。** 每轮启动独立的 Chrome 实例并分配全新的临时用户目录，因此没有可复用的 HTTP 缓存、DNS 缓存与连接池；进入页面后再显式清空浏览器缓存并禁用缓存。Chrome 统一加 `--disable-quic`，使 HTTP/3 不可用；每轮同时检查实际协商协议，若出现 `h3` 则记为"未禁用 QUIC"并让严格校验拒绝该条记录。正式数据要求 `quic_disabled=true`、`cache_mode=cold`。

## 4.3 受控实验平台

平台架在本机 WSL2 中（Ubuntu 24.04，内核 6.6.114），由四部分组成（图 2）：

- **服务端**：nginx 监听 8080，站点根目录放置 1 个索引页与 20 个精确 61440 byte 的合法 PNG，整页共 21 个请求、1 235 397 byte；
- **时延控制**：`tc netem delay 60ms` 作用于 WSL 出口网卡，Windows 侧 ping 实测 RTT 稳定为 65 ms；
- **窗口控制**：`ip route` 为出口网卡上的默认路由与 on-link 网段路由同时设置 `initcwnd`，取 2、4、10、20 四档；
- **测量端**：Windows 侧的 Chrome 通过 HTTP 访问该页面，采集逻辑与真实站点完全一致。

有两个实现细节直接影响数据可信度。第一，initcwnd 必须写在**回程实际使用的那条路由**上：WSL2 中客户端与服务器同处一个虚拟子网，响应包走的是 on-link 网段路由而不是默认路由，只改默认路由时设置不生效，单连接下载 60 KB 对象的实测差异可以证明这一点（改前 0.40 s、改后 0.20 s）。第二，WSL2 虚拟机会在空闲数秒后自动关机，采集期间必须保持一个常驻会话，否则页面请求会被直接拒绝。

每组切换参数后先确认 `tc qdisc` 与 `ip route` 已生效再开始采集，采集结束立刻清除 netem 规则并恢复 initcwnd，避免污染后续的真实站点测量。

## 4.4 浏览器测量方案

测量程序通过 Chrome DevTools 协议（CDP）驱动浏览器，而不是依赖页面内埋点或命令行 `--dump-dom`，原因是前者能精确等到 load 事件、并在同一浏览器上下文中读到 Navigation Timing。流程为：启动 Chrome 并暴露调试端口，连接 websocket 后启用 `Page`、`Network`、`Runtime` 三个域；`Page.navigate` 发起请求，等待 `Page.loadEventFired`；随后用 `Runtime.evaluate` 读取 `PerformanceNavigationTiming` 与 `performance.getEntriesByType("resource")`，换算为六个时间指标、请求数与传输字节。

指标映射严格按第 2 章的定义：`dns_ms = domainLookupEnd - domainLookupStart`，`tcp_ms = connectEnd - connectStart`，`tls_ms = connectEnd - secureConnectionStart`，`ttfb_ms = responseStart - requestStart`，`dom_content_loaded_ms` 与 `load_ms` 取两个事件的结束时刻，全部相对 `navigationStart` 计算。

## 4.5 多轮统计与异常剔除

每个站点保留 5 轮原始记录，不预先做人工筛选。站点级统计先按 `load_ms` 用四分位距（IQR）判定异常：超出 `Q1 - 1.5×IQR` 到 `Q3 + 1.5×IQR` 的轮次剔除，样本数小于 4 时不剔除；剔除数量与发生位置写入实验记录。随后取剩余轮次的中位数作为该站点的代表值，再与 initcwnd 合并，避免均值被个别长尾轮次拉偏。

## 4.7 平台有效性校核

在正式采集前，用受控平台做一次有效性校核：同一页面、同一 RTT，只改变 initcwnd，四组各 5 轮。`load_ms` 中位数依次为 728.4、599.3、595.2、467.6 ms，随 initcwnd 单调下降；`ttfb_ms` 稳定在 65.8~66.1 ms，`transfer_bytes` 恒为 1 235 397 byte，20 轮全部通过字段校验。页面内容与时延不变而加载时间随窗口改变，说明平台成功隔离了其他变量，四档参数也确实作用于回程路径。这组数据同时为第 5 章的受控实验对比提供了基线。

## 4.8 本章小结

真实站点线以可达性预检确定的 25 个站点、5 轮冷缓存采集得到外部数据；受控线用 WSL2 + nginx + netem + initcwnd 构造可重复的内部验证环境，并通过有效性校核确认参数生效。两条线的原始记录都通过 `validate_pageload` 严格校验后写入 `data/processed/pageload.csv`，异常剔除规则与实验环境在中位数计算之前就已记录在案。
