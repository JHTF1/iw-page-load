# 数据字典

本文件说明 `data/processed/` 下两份 CSV 的字段、单位、取值范围与校验规则。字段定义以 `src/common/schema.py` 为准，两者必须同步。

**修改规则**：任何字段的增删改都属于公共契约变更，必须走 PR，三人确认后同时改 `schema.py` 与本文件。

---

## 一、通用约定

- 编码：UTF-8，不带 BOM
- 分隔符：英文逗号
- 首行：字段名，顺序与 `schema.py` 一致
- 时间：统一 UTC，ISO 8601，例如 `2026-11-04T02:15:30Z`
- 时间量单位：毫秒（ms），保留 1 位小数
- 字节量单位：byte，整数，不带单位后缀
- 缺失值：留空，不得填 `0`、`-1`、`N/A` 等替代值
- 布尔值：写 `true` / `false`

## 二、initcwnd.csv

产出者：A。路径：`data/processed/initcwnd.csv`。

**site**（字符串，必填）
站点标识，必须与 `pageload.csv` 的 `site` 完全一致。受控实验写 `lab-2`、`lab-4`、`lab-10`、`lab-20`，其余为真实站点标识，与 `config/sites.csv` 的 `site` 列一致。

**url**（字符串，必填）
被测 URL，真实站点为首页地址；受控实验为测试对象 URL（例如 `http://<wsl-ip>:8080/obj-01.png`），initcwnd 校准必须请求足够大的对象以填满首窗口。

**server_ip**（字符串，必填）
服务器 IP 字面量，IPv4 或 IPv6。用于抓包过滤与人工复核。

**ip_version**（字符串，必填）
取值 `4` 或 `6`。

**timestamp_utc**（字符串，必填）
采集开始时间，ISO 8601 UTC。

**initcwnd_bytes**（整数，必填，单位 byte）
服务器在客户端首次确认其数据（ACK 号大于服务器 ISN）之前发出的去重载荷字节数，必须大于 0。真实 HTTPS 站点的首飞可能受 TLS 握手数据量限制，所得字节数是配置窗口的下界；受控实验用于校准。

**mss_bytes**（整数，必填，单位 byte）
MSS，取客户端 SYN 与服务器 SYN-ACK 的 MSS 选项中的较小值，必须大于 0；两者不同说明路径 MTU 不一致。任一侧 MSS 非正或缺失时视为无效，按另一侧或协议默认值回退并降低置信度。不得写死 1460。

**initcwnd_mss**（浮点数，必填，单位 MSS）
必须等于 `initcwnd_bytes / mss_bytes`，允许误差 0.1，超出即判为计算错误。

**segment_count**（整数，必填，单位 段）
首窗口内观察到的报文段数量。**仅供参考，不得作为结论依据**：网卡 GRO/LRO 会把多个段合并，段数会失真。

**retrans_count**（整数，必填，单位 段）
首窗口内判定为重传的报文段数量。

**method**（字符串，必填）
取值 `passive`（真实站点）或 `lab`（受控实验）。校验规则：`site` 以 `lab-` 开头时必须为 `lab`，否则必须为 `passive`。

**confidence**（字符串，必填）
取值 `high`、`medium`、`low`。判定标准：握手完整、首窗口边界清晰为 high；存在轻微重传或乱序但仍可确定为 medium；边界不清晰为 low，low 的数据必须复核。

**notes**（字符串，可选）
异常情况说明，例如"首窗口内有 2 个重传，已按序号去重"。

## 三、pageload.csv

产出者：B。路径：`data/processed/pageload.csv`。

**site**（字符串，必填）
站点标识，与 `initcwnd.csv` 一致。

**url**（字符串，必填）
被测 URL。

**run_id**（整数，必填）
同一站点的轮次编号，从 1 开始。

**timestamp_utc**（字符串，必填）
该轮采集开始时间，ISO 8601 UTC。

**dns_ms**（浮点数，必填，单位 ms，≥0）
DNS 解析耗时。命中缓存时记录实际值并在 `notes` 注明。

**tcp_ms**（浮点数，必填，单位 ms，≥0）
TCP 连接耗时。

**tls_ms**（浮点数，必填，单位 ms，≥0）
TLS 握手耗时。纯 HTTP 站点填 0 并在 `notes` 注明。

**ttfb_ms**（浮点数，必填，单位 ms，≥0）
首字节时间：从请求发出到收到第一个响应字节。

**dom_content_loaded_ms**（浮点数，必填，单位 ms，≥0）
DOMContentLoaded 事件时间。

**load_ms**（浮点数，必填，单位 ms，≥0）
load 事件时间。

**request_count**（整数，必填，≥0）
页面加载过程中的资源请求总数。

**transfer_bytes**（整数，必填，单位 byte，≥0）
页面加载总传输字节，用于控制"页面大小"这个混杂变量。

**quic_disabled**（布尔，必填）
是否禁用 QUIC。正式数据必须为 `true`。为 `false` 的数据不得进入分析。

**cache_mode**（字符串，必填）
取值 `cold` 或 `warm`。正式数据必须为 `cold`。

**network_env**（字符串，必填）
网络环境描述，例如"有线 · 中国移动 · 2026-11-04 10:00-11:00"。

**notes**（字符串，可选）
异常说明，例如"第 3 轮首包超时，已剔除"。

## 四、校验与使用规则

1. 写入前：产出方负责跑 `validate_initcwnd` / `validate_pageload`，不通过不得写入。
2. 进入分析前：C 的 `python -m src.analysis` 会再校验一遍，不通过直接退出，不得跳过。
3. 异常值：按四分位距（IQR）规则剔除，剔除条数与规则必须写进实验记录和报告。
4. 合并键：`site`。同一站点多轮数据先按站点聚合（中位数），再与 initcwnd 合并。
5. 受控实验与真实站点分开统计，不得混在一组里算相关系数。

## 五、最终核对（2026-11-04，C）

本核对只读取冻结数据，不回写 CSV。

**行数与校验**

- `initcwnd.csv`：29 行，其中真实站点 25 行、受控实验 4 行（lab-2、lab-4、lab-10、lab-20）；全部通过 `validate_initcwnd`。
- `pageload.csv`：142 条，其中真实站点 122 条、受控实验 20 条；全部通过 `validate_pageload`。
- 合并后 29 个站点；真实站点 25 个、lab 4 个，分组规则与 `site` 前缀一致。

**IQR 复核**

- 以 `load_ms` 为判据、样本少于 4 轮不剔除：真实站点保留 108/122 轮，受控实验保留 16/20 轮。
- 剔除只用于站点级中位数与箱线图，不修改原始 CSV；复核记录见 `docs/实验记录.md` 的 EXP-20261104-02。

**已知数据质量提示**

- amazon、yahoo 命中的是防爬拦截页（传输 1 633 B / 3 669 B，请求数 2 / 3），加载时间不代表正常首页；保留以避免选择性删除，解释时须标注。
- microsoft 的 `initcwnd` 只有 1/2 轮有效（第 1 轮 curl 超时 8 000 ms），3.01 MSS 由单轮首飞折算。
- 真实 HTTPS 首飞可能受 TLS 握手数据量限制，`initcwnd_bytes` 是服务器配置窗口的下界，不是精确配置值。
- 36kr 有 2 轮 `load_ms=0`，疑为跳转或失败页；按 IQR 未被剔除，剔除后 load 中位数 315.0 ms，相关系数 −0.304（p=0.139），结论不变。
- 36kr、amazon、microsoft、stackoverflow、xiaohongshu、zhihu 共 6 个 HTTPS 站点存在 `tls_ms=0` 的记录；该字段不参与任何推断，分析结论不受影响。
